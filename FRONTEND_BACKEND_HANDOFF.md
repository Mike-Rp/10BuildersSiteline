# Frontend fixes and backend handoff

- ADM-ARCH-003: Frontend API client blocks ordinary project DELETE requests. No project deletion button exists in the current UI. Backend must reject active-project deletion and enforce archive eligibility.
- SHR-NOT-007: Recommendation requests require a session token in the frontend. All authenticated 401 responses now clear the session and notify the app. Backend must authenticate every recommendation endpoint.
- SHR-NOT-008: Temporary-password sessions display password reset without loading workspace data. Frontend blocks other API requests until reset succeeds, then re-verifies the session. Backend must enforce the restriction for every protected endpoint.
- ADM-INT-011 / WF-INT-002: Resubmission workspace payload clears OPM acceptance timestamp and team confirmations. Backend intake transaction must invalidate the former OPM confirmation and issue a fresh pending confirmation to the replacement OPM; frontend cannot repair stale database confirmation records.
- SPM-DASH-004: Engineer responsibility acceptance now uses the same prerequisite checks as assignment acceptance, both on the button and in its action handler. Backend must enforce OPM acceptance, six registered documents, and lead-first acceptance.
- ADM-ALLOC-005: Frontend validation and helper text allow at least 50% coverage for every phase, rounded up; 2 of 3 passes. Backend engineer-phase-coverage policy still uses the old quota for phases below five tags and must be updated. Existing backend suggestion logic remains in use and prefers full coverage.

Backend source files were not modified. Production build and focused regression tests are run locally; live-site behavior is not verified.

## Backend status (2026-11-11)

Backend fixes for the items above are implemented and covered by tests (`Thesis-Backend/tests/capstone-guards.test.js`, `tests/capstone-fixes-backend.test.mjs`, plus assertions added to `tests/phase-foreman-backend.test.mjs`).

- ADM-ARCH-003: `DELETE /projects/:id` answers 409 `PROJECT_ACTIVE` for active projects and 409 `PROJECT_ARCHIVED` for archived ones before any record changes. Intake-stage projects remain removable by Administrators.
- SHR-NOT-007: `/projects/recommendations`, `/recommendations/rerun` and `/recommendations/swap-opm` require an Administrator or Office PM session (401 signed out, 403 other roles). Recommendation rows now also carry `coverage_quota` and `quota_met`.
- SHR-NOT-008: while `temp_password_issued` is true, every session-backed request other than `GET /auth/me`, `/auth/session`, `/auth/activity`, `POST /auth/reset-password`, `POST /auth/admin/change-password`, refresh and sign-out answers 403 with `error.code` `PASSWORD_CHANGE_REQUIRED`. The flag clears only after a successful password change. The frontend should treat that code like the local block (show the reset screen) in case the local flag is ever out of sync.
- ADM-INT-011 / WF-INT-002: `POST /projects/intake` with `draft_project_id` is a correction, accepted while the project is in `draft`, `suggested_allocation`, `confirmed`, `sent_to_opm` or `spm_review` (still refused once a Site PM has accepted). It marks every open Office PM confirmation `reassigned`, ends the former OPM's oversight assignment, returns the project to `sent_to_opm`, re-creates the phase team as pending and inserts a fresh pending confirmation linked through `reassigned_from_id`, all in one transaction. Declined confirmations stay as recorded; audit events `opm_confirmation_superseded` and `intake_resubmitted` are written. `POST /confirmations/:id/accept` refuses an OPM who is no longer the project's assigned OPM (409 `OPM_CONFIRMATION_SUPERSEDED`). The resubmission response is no longer "Project was already submitted"; only `intake_id` replays without `draft_project_id` are treated as duplicates.
- SPM-DASH-004: phase-team acceptance and engineer-responsibility acceptance both require OPM acceptance, the six registered documents and a confirmed Lead Site PM first (409 `OPM_ACCEPTANCE_REQUIRED`, `REGISTERED_DOCUMENTS_REQUIRED`, `LEAD_ACCEPTANCE_REQUIRED`). Declines are unchanged.
- ADM-ALLOC-005: `phaseCoverageQuota` is `ceil(unique tags / 2)` for every phase; intake, allocation updates, activation coverage and recommendations all use it. At most three engineers per phase applies to every phase size; the allocator prefers full coverage with the fewest engineers and otherwise returns the team with the most coverage.
